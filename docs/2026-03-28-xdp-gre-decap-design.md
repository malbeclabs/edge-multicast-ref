# XDP GRE Decapsulator — Design Spec

**Date:** 2026-03-28
**Status:** Draft
**Scope:** Standalone XDP program that strips GRE encapsulation inline, delivering clean multicast UDP packets to the kernel stack

## Overview

A standalone XDP program that decapsulates GRE-wrapped multicast packets directly on the physical NIC, rewriting them as plain Ethernet/IP/UDP frames before passing them to the kernel. This lets any standard sockets-based application receive DoubleZero shred and heartbeat traffic without GRE tunnel interfaces, AF_XDP, or custom packet parsing.

**Target audience:** Operators who want existing multicast-capable applications (e.g. Solana validators, shredstream-proxy) to receive DoubleZero edge feeds with no application changes.

**Relationship to other implementations:** This is a separate tool from the AF_XDP reference receivers. Those redirect packets to userspace for custom processing; this one transforms packets and hands them back to the kernel. They should not be attached to the same interface simultaneously.

## Motivation

The existing reference designs require either:
- A GRE tunnel interface (`doublezero1`) that the kernel manages — adds latency and requires tunnel configuration
- AF_XDP with custom userspace — powerful but complex, requires application changes

An XDP decapsulator gives a middle path: packets arrive on the physical NIC as GRE, the XDP program strips the encapsulation at line rate, and the kernel sees ordinary multicast UDP. Applications just `bind()` to the multicast group and port as if the packets were native.

## Packet Transformation

### Before (wire format on physical NIC)

```
┌──────────┬───────────┬──────────────┬───────────┬─────┬─────────┐
│ Ethernet │ Outer IP  │     GRE      │ Inner IP  │ UDP │ Payload │
│ 14 bytes │ 20+ bytes │  4-16 bytes  │ 20+ bytes │ 8 B │         │
│ dst=NIC  │ proto=47  │ proto=0x0800 │ dst=mcast │     │ shred/  │
│ src=peer │ dst=local │ C/K/S flags  │ proto=17  │     │ hbeat   │
└──────────┴───────────┴──────────────┴───────────┴─────┴─────────┘
```

### After (what the kernel sees)

```
┌──────────┬───────────┬─────┬─────────┐
│ Ethernet │ Inner IP  │ UDP │ Payload │
│ 14 bytes │ 20+ bytes │ 8 B │         │
│ dst=mMAC │ dst=mcast │     │ shred/  │
│ src=orig │ proto=17  │     │ hbeat   │
└──────────┴───────────┴─────┴─────────┘
```

Where `mMAC` is the multicast MAC derived from the inner destination IP (01:00:5e:xx:xx:xx).

### Bytes stripped

The program removes `outer_ihl + gre_len` bytes from between the Ethernet header and the inner IP header:

| GRE flags | Outer IHL | GRE len | Total stripped |
|-----------|-----------|---------|----------------|
| None      | 20        | 4       | 24 bytes       |
| C+K+S     | 20        | 16      | 36 bytes       |
| Typical   | 20        | 8-12    | 28-32 bytes    |

## Language Choice

**eBPF program:** C — the existing `go/xdp-receiver/bpf/xdp_filter.c` provides a proven parsing template. C is the most portable eBPF language and this program has no need for Rust's aya framework (no AF_XDP maps, no complex userspace integration). Any operator with clang can build it.

**Loader/CLI:** Go with cilium/ebpf — consistent with the existing Go tooling in the repo. Embeds the compiled eBPF object via `//go:embed`, handles config map population, interface attachment, stats reporting, and clean detach on signal. Alternatively, the compiled `.o` can be loaded directly with `ip link set dev eth0 xdp obj gre_decap.o` for environments where a custom loader isn't wanted.

## eBPF Program Design

### Entry point

```c
SEC("xdp")
int xdp_decap(struct xdp_md *ctx)
```

### Maps

```c
/* Configuration: which packets to decapsulate */
struct decap_config {
    __u32 multicast_ip;     /* network byte order — 0 means "decap all GRE" */
    __u16 shred_port;       /* host byte order — 0 means "don't filter on port" */
    __u16 heartbeat_port;   /* host byte order — 0 means "don't filter on port" */
};

struct {
    __uint(type, BPF_MAP_TYPE_ARRAY);
    __uint(max_entries, 1);
    __type(key, __u32);
    __type(value, struct decap_config);
} config SEC(".maps");

/* Per-CPU stats */
struct decap_stats {
    __u64 decapped;     /* packets successfully decapsulated */
    __u64 passed;       /* packets passed through untouched */
    __u64 errors;       /* parse errors or failed adjustments */
};

struct {
    __uint(type, BPF_MAP_TYPE_PERCPU_ARRAY);
    __uint(max_entries, 1);
    __type(key, __u32);
    __type(value, struct decap_stats);
} stats SEC(".maps");
```

### Algorithm

```
1.  Parse Ethernet header (14 bytes)
    - If EtherType != 0x0800 → XDP_PASS

2.  Parse outer IPv4 header
    - Read IHL, compute outer_ihl = (IHL & 0x0F) * 4
    - If protocol != 47 (GRE) → XDP_PASS

3.  Parse GRE header at offset 14 + outer_ihl
    - If GRE protocol != 0x0800 → XDP_PASS
    - Compute gre_len from C/K/S flags (4 to 16 bytes)

4.  Parse inner IPv4 header at 14 + outer_ihl + gre_len
    - Read destination IP
    - If config.multicast_ip != 0 and doesn't match → XDP_PASS
    - Optionally check UDP dst port against config

5.  Save original source MAC (6 bytes) from Ethernet header

6.  Compute multicast destination MAC from inner IP:
      dst_mac[0] = 0x01
      dst_mac[1] = 0x00
      dst_mac[2] = 0x5e
      dst_mac[3] = (inner_dst_ip >> 8)  & 0x7f   /* second octet, high bit masked */
      dst_mac[4] = (inner_dst_ip >> 16) & 0xff    /* third octet */
      dst_mac[5] = (inner_dst_ip >> 24) & 0xff    /* fourth octet */
    (inner_dst_ip is in network byte order, so byte offsets are reversed)

7.  strip_len = outer_ihl + gre_len
    Call bpf_xdp_adjust_head(ctx, strip_len)
    - This advances ctx->data by strip_len bytes
    - The packet now starts where the inner IP header was
    - If this fails → inc_errors(), XDP_PASS

8.  Write new Ethernet header (14 bytes) before the inner IP:
    - Re-read ctx->data / ctx->data_end (they changed after adjust_head)
    - Bounds check: data + 14 <= data_end
    - Write dst_mac (multicast MAC computed above)
    - Write src_mac (saved from original header)
    - Write EtherType = 0x0800

9.  inc_decapped()
    Return XDP_PASS — kernel now processes a clean multicast frame
```

### Verifier considerations

- All pointer arithmetic uses the cursor-plus-bounds-check pattern from the existing `xdp_filter.c`
- `bpf_xdp_adjust_head` invalidates `data`/`data_end` pointers — must re-read from `ctx` after the call
- The MAC addresses are saved to stack variables (12 bytes) before `adjust_head`
- Variable offsets (outer_ihl, gre_len) stay within bounds enforced by the parsed values

### What about bpf_xdp_adjust_head and headroom?

`bpf_xdp_adjust_head(ctx, delta)` with a **positive** delta moves `data` forward (shrinks the packet from the front). We're removing bytes, so delta is positive. This is well-supported on all XDP-capable drivers (both native and generic/SKB mode). No headroom concerns — we're shrinking, not growing.

## Go Loader Design

### CLI flags

```
gre-decap [flags]
  -i, --interface string     Physical NIC to attach to (required)
  -g, --group string         Multicast group IP to decap (default: decap all GRE)
  -m, --mode string          XDP attach mode: "native", "skb", "auto" (default: "auto")
  -s, --stats-interval dur   Stats reporting interval (default: 1s, 0 to disable)
```

No port flags by default — decapsulate all traffic destined for the multicast group. Port filtering can be added but most users will want everything decapped.

### Startup sequence

```
1.  Parse flags, resolve interface index
2.  Load eBPF object (embedded via bpf2go)
3.  Populate config map:
    - multicast_ip = parsed group IP (or 0 for "all")
    - shred_port = 7733 (hardcoded default)
    - heartbeat_port = 5765 (hardcoded default)
4.  Attach XDP program to interface
    - Try native mode first, fall back to SKB if it fails (unless explicit mode)
5.  Print "attached to eth0 (native mode), decapping 233.84.178.1"
6.  Poll stats map every stats-interval, print one-line summaries:
      "decapped=142390  passed=8201  errors=0  (142390 pps)"
7.  On SIGINT/SIGTERM:
    - Detach XDP program
    - Close eBPF objects
    - Print final stats
```

### Stats reporting

Read the per-CPU stats map, sum across CPUs, compute delta from last read for rate calculation. Simple single-line output to stdout — no TUI needed for this tool.

## Interaction with GRE Tunnel Interface

**The XDP decap program and the `doublezero1` GRE tunnel interface are mutually exclusive for matched packets.** When the XDP program decapsulates a GRE packet and returns `XDP_PASS`, the kernel receives a rewritten frame that is no longer GRE (it's now plain multicast UDP). The kernel's GRE tunnel module never sees it, so `doublezero1` receives nothing for that packet.

- **Matched packets** (GRE, correct multicast group) — decapped by XDP, delivered as multicast UDP on the physical interface. The tunnel interface does not see them.
- **Unmatched packets** (non-GRE, different group, or config set to filter specific groups) — passed through untouched. If they're GRE, the tunnel interface processes them normally.

This means you cannot run the XDP decap program and simultaneously have applications listening on `doublezero1` for the same traffic. Choose one path or the other. If you need both during a migration, configure the XDP program to filter a specific multicast group and leave other GRE traffic for the tunnel.

## Kernel-Side Requirements

After decapsulation, the kernel sees a standard multicast UDP packet. For applications to receive it:

1. **Multicast group membership** — the receiving application (or `ip maddr add`) must join the multicast group on the **physical interface** (e.g. `eth0`), not the tunnel interface
2. **Reverse path filtering** — may need to be relaxed since the source IP (148.51.x.x) isn't reachable via the physical NIC's routing table:
   ```
   sysctl -w net.ipv4.conf.eth0.rp_filter=0
   ```
3. **No GRE tunnel interface needed** — the whole point is to eliminate the tunnel

## Testing

### Unit testing with pcaps

Load the compiled eBPF object in `BPF_PROG_TEST_RUN` mode and feed it raw packets from the existing `pcaps/` directory. Verify:
- GRE multicast packets → returned packet has Ethernet + inner IP + UDP (no outer IP / GRE)
- Non-GRE packets → passed through unchanged
- Correct multicast MAC in rewritten Ethernet header

### Integration testing

```bash
# Attach to physical NIC
sudo ./gre-decap -i eth0 -g 233.84.178.1

# In another terminal, verify multicast arrives on the raw interface:
sudo tcpdump -i eth0 -n 'udp and dst 233.84.178.1'

# Or with a standard multicast receiver:
socat UDP4-RECVFROM:7733,ip-add-membership=233.84.178.1:eth0,fork -
```

### Comparison with tunnel interface

Run both the GRE tunnel path and the XDP decap path, compare:
- Packet content is identical (beyond the stripped headers)
- Latency improvement from skipping tunnel processing

## Limitations and Non-Goals

- **Single interface** — attaches to one NIC at a time (run multiple instances for multiple NICs)
- **IPv4 only** — no IPv6 GRE handling (the DoubleZero feed is IPv4)
- **No tunnel metadata** — GRE key/sequence values are discarded, not exposed
- **No reassembly** — the XDP program does not handle IP fragments (shred packets are well under MTU)
- **No heartbeat response** — this is receive-only, same as the other reference designs
- **Not composable with AF_XDP receivers** — only one XDP program per interface
- **No FEC recovery** — just decapsulation, not shred processing

## Future Considerations

- **Multi-group support** — use a BPF hash map of multicast IPs instead of a single config entry
- **VLAN tagging** — if the inner packet needs a VLAN tag for routing, could be added with `bpf_xdp_adjust_head` in the other direction
- **Metrics export** — expose stats via a prometheus endpoint or BPF ring buffer for external monitoring
- **tc/clsact alternative** — if XDP native mode isn't available, the same logic could work as a tc-bpf program (with `bpf_skb_adjust_room` instead of `bpf_xdp_adjust_head`)
